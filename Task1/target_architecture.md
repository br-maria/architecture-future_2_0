# Task1 — C4 Container: описание целевой архитектуры (через 1 год)

Диаграмма контейнеров находится в файле `c4_container_diagram.png`.

## Ключевая идея
Перейти от «монолитного DWH с логикой» к **облачной платформе данных (lakehouse)** и **доменному подходу (data products / data mesh)**:
- каждый домен (Клиники, Финтех, HR, Инвентарь и т. д.) развивает свои наборы данных независимо, публикуя **контрактованные data products**;
- общий слой **Governance & Security** обеспечивает единые правила доступа, аудит, классификацию, маскирование/анонимизацию, lineage и каталог;
- «витрина данных» — это **портал самообслуживания** + **семантический слой** + BI, работающие по доменным продуктам.

Важно: **медицинские карты, истории болезни и результаты исследований не входят в аналитику** и остаются в клиническом контуре (с отдельными политиками доступа).

## Контейнеры (что где живёт)
1. **Операционные системы доменов**
   - Клиники (регистратура/приём/операционные данные, счета, инвентарь и т. п.).
   - Финтех core-сервисы (банк).
   - ИИ‑сервисы (работают с медданными в своём контуре).
   - Партнёры (фарма и производитель оборудования).

2. **Интеграционный слой**
   - **API Gateway** для B2B/B2C интеграций и управления контрактами API.
   - **Event Streaming (Kafka/PubSub) + Schema Registry** для событий и асинхронной интеграции.
   - **ELT Orchestration + Data Quality** (Airflow/ADF + DQ) для загрузок в платформу данных.

3. **Облачная платформа данных (Lakehouse)**
   - Зоны **Raw / Curated / Serving** (сырьё → проверенные доменные наборы → представления для потребления).
   - **Доменные data products**: наборы данных с владельцем, контрактом, версионированием, SLA/SLO.

4. **Потребление данных**
   - **Портал «витрина данных»**: каталог, поиск, запрос доступа, готовые отчёты и конструктор.
   - **Семантический слой**: единые метрики, справочники/MDM, Row-Level Security.
   - **BI (Power BI)**: дашборды и ad-hoc отчёты на Serving/семантике.

5. **Governance & Security (сквозной контур)**
   - IAM (RBAC/ABAC), шифрование, DLP, аудит, политики хранения, lineage, каталог.

## Как архитектура поддерживает бизнес‑сценарии
- **Быстрая отчётность**: Serving‑слой + предрасчёты + семантика → меньше «трансформаций на лету», отчёты минутами, а не часами.
- **Независимое развитие финтех/ИИ/клиник**: доменные продукты и контракты уменьшают связанность, изменения локализуются.
- **Подключение новых бизнесов**: партнёры подключаются через API/Event Bus, данные попадают в доменные зоны по стандартам.
- **Надёжность в облаке**: Multi-AZ/Region, резервное копирование, DR‑план, наблюдаемость пайплайнов.
- **Соответствие регуляторам**: изоляция сред по доменам, строгие политики доступа, аудит и маскирование.
